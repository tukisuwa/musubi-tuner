# MiniMax-H3で複数の画像をまとめて生成する（MFI）

[English](minimax_h3_mfi.md)

MFIは、複数の画像をまとめて生成する機能です。出力画像ごとにインデックス（モデル上の座標）を指定し、学習時と同じ対応関係で生成します。画像は1枚ずつ保存されますが、生成中は互いの情報を参照します。

出力の数や役割は、MFI自体が決めるものではありません。例えば、インデックスに`-6`を指定しただけで、特定の種類の画像が出るわけではありません。どの座標にどの画像を対応させるかは、学習データと設定で決めます。

この機能は実験的なもので、`--h3_independent_target_roles`を指定した場合だけ有効になります。

## 最初に押さえる用語

- **ターゲット**：生成したい画像。学習時には正解画像を用意します。
- **コントロール（参照画像）**：生成の手がかりとして与える画像。ターゲットとは別の入力です。
- **インデックス**：各ターゲットと参照画像に割り当てる整数の座標。負の値も使えます。単なる出力番号ではなく、モデルの位置表現に使われます。
- **latent（潜在表現）**：画像などを、モデルが処理するための数値データに変換したものです。VAEが画像とlatentを相互に変換します。
- **キャッシュ**：画像やテキストを事前に変換して保存した学習用データです。学習のたびに変換し直す必要がなくなります。

本文で使うモデル名は、Qwenがテキストや参照画像から特徴を取り出すモデル、DiTがノイズを除去して画像を生成するモデルを指します。

この文書では、参照画像を座標`0`、2枚のターゲットを座標`-6`と`8`に対応させる例を使います。これらは説明用の値で、MFIの既定値や固定の役割ではありません。

## 目的に合った手順を選ぶ

| やりたいこと | 使用する処理 |
| --- | --- |
| 学習済みLoRAで画像を生成する | `minimax_h3_generate_video`：次の「生成する」を参照 |
| 自分のデータでLoRAを学習する | `minimax_h3_cache_mfi`でキャッシュ作成 → `minimax_h3_train_network`で学習 |
| 学習の途中で出力を確認する | 学習中のサンプル生成：学習用データとは別にプロンプトと参照画像を指定 |

生成用のオプションを、そのまま学習にも使えるとは限りません。特に補間、初期画像、strength、連番動画出力は生成用です。詳しい対応範囲は後半にまとめています。

## 生成する

### 1. モデルと学習時の設定を確認する

H3のモデル、VAE、Qwen、参照画像、目的に合った学習済みLoRAを用意します。ターゲットの数・順序・インデックス、参照経路、ノイズの設定は、そのLoRAの学習時の設定に合わせてください。

以下のコマンドは、参照座標`0`、ターゲット座標`-6,8`、独立ノイズで学習したLoRAを使う例です。パスとプロンプトは実際のものに置き換えてください。モデル形式やメモリ退避の設定については、[H3のドキュメント（英語）](minimax_h3.md)も参照してください。

### 2. 生成コマンドを実行する

```bash
python minimax_h3_generate_video.py \
  --task ref2va \
  --dit /path/to/ref2va_dit.safetensors \
  --video_vae /path/to/video_vae.safetensors \
  --audio_vae /path/to/audio_vae.safetensors \
  --text_encoder /path/to/qwen3-vl \
  --ref /path/to/reference.png \
  --prompt "generate the jointly trained output roles" \
  --lora_weight /path/to/multi_role_lora.safetensors \
  --width 512 --height 512 --steps 20 --seed 1 \
  --h3_independent_target_roles \
  --h3_target_frame_indices=-6,8 \
  --h3_visual_condition_frame_indices=0 \
  --h3_target_noise_coupling independent \
  --h3_reference_route dual \
  --output_type latent_images --output outputs/mfi
```

主な指定の意味は次のとおりです。

- `--h3_independent_target_roles`：MFIを有効にします。
- `--h3_target_frame_indices=-6,8`：この順序で2枚を生成します。
- `--h3_visual_condition_frame_indices=0`：参照画像に座標`0`を割り当てます。
- `--output_type latent_images`：画像と、再デコードに使えるlatentの両方を保存します。

### 3. 出力を確認する

出力先には`000_index_-6.png`と`001_index_+8.png`が保存されます。先頭の`000`、`001`は出力順、`index_`の後は指定した座標です。

MFIでは、生成枚数を`--frame_count`で指定しません。基本の生成枚数はターゲットインデックスの数で決まります。補間を有効にした場合は、後述の追加ターゲットも内部で生成します。

出力形式は次の3つから選べます。

- `latent`：latentのみ。
- `images`：画像のみ。
- `latent_images`：latentと画像の両方。

## 自分のデータで学習する

基本の流れは「画像の対応を記述する → キャッシュを作る → 学習を実行する」です。ここではJSONL形式のmanifestを使います。manifestは、参照画像・正解画像・座標の対応を記したファイルです。

### 1. 画像の対応を記述する

次の1行を`dataset.jsonl`へ記述します。JSONLでは、1行が1つの学習サンプルです。相対パスは、このファイルのあるディレクトリを基準に解決されます。

```json
{"id":"example","caption":"a character turning around","relative":true,"controls":[{"path":"reference.png","index":10,"mask":"mask.png"}],"targets":[{"path":"before.png","index":4},{"path":"after.png","index":18}]}
```

- `controls`：参照画像です。この例では`reference.png`を使います。
- `targets`：正解画像です。`before.png`、`after.png`の順序で学習します。
- `index`：それぞれの画像に割り当てる座標です。
- `relative: true`：最小の参照座標を引き、相対座標へ変換します。
- `mask`：参照画像のマスクです。使わない場合は、このフィールドを削除してください。

この例では全座標から`10`を引くため、キャッシュに保存される座標は次のようになります。

| 画像 | 指定した座標 | キャッシュ内の座標 |
| --- | --- | --- |
| `reference.png` | 10 | 0 |
| `before.png` | 4 | -6 |
| `after.png` | 18 | 8 |

別のサンプルでは、画像数や座標が異なっていても構いません。ただし、何をどの順序・座標で学習させるかは、意図したルールで揃えてください。

### 2. キャッシュを作る

画像などのlatentを作る処理と、Qwenの特徴を作る処理を、順に別プロセスで実行します。モデルが同時に常駐するのを避けるためです。

```bash
python -m musubi_tuner.minimax_h3_cache_mfi \
  --manifest dataset.jsonl --output cache/mfi --stage latents \
  --video_vae /path/to/video_vae.safetensors \
  --audio_vae /path/to/audio_vae.safetensors --route dual

python -m musubi_tuner.minimax_h3_cache_mfi \
  --manifest dataset.jsonl --output cache/mfi --stage text \
  --text_encoder /path/to/qwen3-vl.safetensors \
  --text_encoder_blocks_to_swap 50 --route dual
```

両方のコマンドで、入力の選択、画像サイズ、seed、相対座標設定、参照経路を一致させてください。上の例では、参照画像をQwenとDiTの両方に渡す`dual`を使用しています。

キャッシュには、設定や入力ファイルを識別する情報（フィンガープリント）が記録されます。対になるキャッシュの整合性はモデル読み込み前に検査されます。

既存キャッシュは上書きされません。設定を変更したときは、新しいディレクトリへ両方のキャッシュを作成してください。

### 3. データセット設定を作る

例えば、次の内容を`dataset.toml`へ保存します。パスは実際のディレクトリへ置き換えてください。

```toml
[general]
resolution = [512, 512]
batch_size = 1

[[datasets]]
image_directory = "/path/to/source_images"
cache_directory = "/path/to/cache/mfi"
```

現在のH3学習器はバッチサイズ1を使用します。ターゲット数や参照画像数が異なるサンプルを、同じ学習実行に含められます。実効的なバッチサイズを増やすには勾配累積を使用できます。

### 4. 学習を実行する

以下は、キャッシュに保存された座標を使って学習する例です。モデルと設定ファイルのパスを置き換え、学習期間、オプティマイザー、メモリ設定を用途に合わせて調整してください。

```bash
accelerate launch -m musubi_tuner.minimax_h3_train_network \
  --task ref2va --dataset_config /path/to/dataset.toml \
  --dit /path/to/ref2va_dit.safetensors \
  --output_dir outputs/mfi_training --output_name multi_role_lora \
  --video_only --mixed_precision bf16 \
  --network_module networks.lora_minimax_h3 --network_dim 8 --network_alpha 8 \
  --h3_independent_target_roles \
  --h3_target_noise_coupling independent \
  --h3_reference_route dual
```

`--output_dir`は重みの保存に必要です。有効な既定の保存先はありません。

この例では、`--h3_target_frame_indices`と`--h3_visual_condition_frame_indices`を省略しています。省略すると各サンプルのキャッシュ内の座標を使います。明示する場合は、キャッシュと同じ値でなければエラーになります。上のmanifestなら`--h3_target_frame_indices=-6,8 --h3_visual_condition_frame_indices=0`です。

### 5. 学習中にサンプル画像を出す

学習中のサンプル生成には、サンプル用のプロンプトと参照画像を別途指定します。座標は、サンプルプロンプト行に`--h3_target_frame_indices -6,8 --h3_visual_condition_frame_indices 0`と書くか、学習実行全体の引数で指定してください。

学習用キャッシュの座標だけでは、別のサンプル画像の座標を決められません。サンプル生成には明示的な座標が必要です。出力はターゲットごとのPNGになります。

参照経路、ノイズの共有設定、条件ノイズの設定は学習設定を引き継ぎます。ただし、学習用キャッシュの参照latentや、そのマスクは再利用しません。

## 入力データを別の方法で用意する

### 画像をファイル名でグループ化する

`--manifest`の代わりに、`--image_directory images --control_indices 2 --target_indices 0 4`を指定できます。

`name_0000.png`、`name_0001.png`のように、数値部分より前が同じファイルを1グループにします。キャプションは`<prefix>.txt`から読み、なければ`--caption`を使います。

インデックスを明示しない場合は、並べた画像の中央を参照画像、残りをターゲットにします。

### 動画からフレームを選ぶ

`--video_directory videos --num_controls 2 --max_targets 4 --max_frame_distance 32 --samples_per_video 3`では、動画から参照フレームと近傍のターゲットを抽選します。選択はキャッシュ作成時に行われ、同じ入力と`--seed`で再現できます。キャプションは動画に隣接する`.txt`ファイルから読みます。

ターゲット数は毎回固定ではありません。各抽選で、1から「`max_targets`と候補数の小さい方」までの整数を一様に選び、その数だけターゲットを選択します。`--control_indices`と`--target_indices`を明示した場合は、それぞれランダム選択より優先されます。

このターゲット数の抽選方式を導入する前のキャッシュとは、選択結果が変わります。再作成する場合は、新しいディレクトリへ両ステージをまとめて作成してください。

manifestで動画のフレームを明示することもできます。`"path":"clip.mp4","frame":24,"index":8`なら、24 fpsへリサンプリングした動画のフレーム24を選び、モデル座標8を割り当てます。**元動画のフレーム番号と、モデルへ渡す座標は別のものです。**

### 学習データを相対座標にする・マスクを付ける

キャッシュ作成時の`--relative`は、全座標から最小のコントロール座標を引きます。manifestでは、レコードごとの`relative`でこの設定を上書きできます。

参照画像のマスクは、manifestのコントロール項目に`mask`を指定します。効果と注意点は後述の「参照画像にマスクを付ける」を参照してください。

ターゲットと参照画像は、それぞれ単独の画像としてエンコードされます。離れた時刻のフレームを連結し、通常のH3動画としてエンコードしないでください。

## 生成を調整する

この節の相対座標・補間・マスク・初期画像・strength・動画出力の指定は、生成CLI用です。`--from_file`での生成にも使用できます。

**これらの生成用フラグを、学習コマンドや学習中のサンプルプロンプトへコピーしないでください。** 学習CLIでは受理されず、サンプルのテキストプロンプトでは、未知のオプションが警告なしで無視される場合があります。

学習データに相対座標やマスクを適用する場合は、前節のキャッシュ作成設定を使用します。学習本体は準備済みのキャッシュを読むだけで、補間ターゲットの動的な追加や初期画像によるターゲット初期化は行いません。

### 座標を相対値へ変換する

`--h3_relative_positioning`を指定すると、最小の参照座標を全座標から引きます。例えば参照`10`、ターゲット`4,18`は、参照`0`、ターゲット`-6,8`になります。省略すると、指定した座標をそのまま使います。

この変換はQwenのテキスト位置を変えません。視覚座標だけをテキストや音声に対して移動させても、生成結果が同じになるとは限りません。

### 間の座標も生成する

`--h3_interpolate --h3_interpolation_thresholds 2 3`を指定すると、ターゲットと参照画像の座標の間に、生成対象の座標を追加します。最初の閾値は最小の参照座標より前、2番目はそれより後の区間に適用されます。

参照画像だけがある座標は、生成対象にしません。同じ座標をターゲットにも指定している場合は、その座標で参照と生成の両方を行います。

追加画像も、もとの画像と一緒に生成します。画像同士が参照する情報やノイズの形状が変わるため、追加前と比べて、もとのターゲットの結果も変わることがあります。

保存方法は次のように選びます。

- `--h3_interpolate`：内部では追加画像も生成しますが、保存するPNGは要求したターゲットだけで、順序も指定どおりです。
- `--h3_save_interpolated`：補間を有効にし、追加分を含めた全画像を座標の昇順で保存します。

保存latentには、追加分を含む内部レイアウトと、どの画像を出力するかの対応が残ります。別途`--latent_path ... --output_type images`で読み込めば、MFIフラグを再指定せずに同じ画像をデコードできます。

### 画像を動画として並べる

`--h3_sequence_video`を指定すると、座標順に24 fpsで並べた`sequence.mp4`も保存します。

生成していない座標は、直前の画像を表示し続けて埋めます。動きを推定する補間ではありません。中間位置の画像を実際に生成したい場合は、補間閾値を`1 1`にし、追加ターゲットも保存してください。参照画像そのものは自動で動画へ挿入されません。

### 参照画像にマスクを付ける

生成時は、視覚条件ごとに`--h3_control_mask mask.png`を1回ずつ指定します。マスクは、正規化した参照latentのサイズに合わせて面積補間で拡大・縮小されます。

- 白：参照latentの値を残します。
- 黒：条件ノイズを加える前の参照latentをゼロにします。

マスクが作用するのはDiT側の参照情報です。Qwenには画像全体が見えます。また、黒くしても参照トークンやその座標は削除されません。画像の一部をattentionから除外する機能でも、学習の損失計算から除外する機能でもありません。

学習・生成では、マスク適用後に条件ノイズが加わる場合があります。`--h3_visual_cond_clean`の既定値は`0.999`なので、黒い領域も最終入力では完全なゼロにはなりません。

ゼロのまま入力したい場合は`--h3_visual_cond_clean 1`を指定します。この値も、学習と推論で揃える設定として記録してください。計算式は後半の内部仕様に記載しています。

### 初期画像やlatentから生成する

通常の生成はノイズから開始しますが、`--h3_initial_image image.png`を使うと、指定した画像を初期状態にできます。参照画像が生成の手がかりなのに対し、初期画像は生成対象の出発点です。

- 初期画像を1枚指定：すべてのターゲットへ同じ初期画像を使います。
- 展開後のターゲット数だけ繰り返し指定：ターゲットごとに異なる初期画像を使います。
- `--h3_initial_latent source.safetensors`を指定：画像の代わりに`latent_video`を読み込みます。形状は、展開後のターゲットと完全に一致させてください。

`--h3_strength`で開始状態を調整します。初期画像を生成に反映させるには、1未満の値を指定してください。既定値の`1`では、初期画像を指定しても純粋なノイズから開始します。

| 値 | 開始状態 |
| --- | --- |
| `1`（既定値） | 純粋なノイズから開始 |
| `0` | 初期latentをそのまま保持 |
| 0と1の間 | 初期画像／latentにノイズを混ぜ、途中のノイズ時刻から生成 |

strengthは、シフトを適用する前のノイズ時刻の割合です。シフト後に混ぜる映像ノイズの割合そのものではありません。

初期画像を使った推論に対応していても、その入力方法でLoRAを学習したことにはなりません。学習は通常のflow-matching方式のままです。初期画像を前提とした学習を行いたい場合は、別途データと学習方法を定義し、評価してください。

### 補間と初期画像を併用するときの順序

複数の初期画像や初期latentのスライスは、**出力順ではなく、内部で生成するターゲットの順序**へ合わせます。

- 補間なし：指定したターゲットインデックスの順序。
- 補間あり：追加分を含む全ターゲットを、座標の昇順に並べた順序。`--h3_save_interpolated`を指定しなくても、この内部順になります。

例えば、ターゲット`9,-3`、参照`0`、補間閾値`2 3`なら、内部の順序は`[-3,-2,3,6,9]`です。異なる初期画像5枚、またはlatentの5スライスは、この順に用意します。初期画像が1枚だけなら、5か所すべてに複製されます。

`--h3_interpolate`だけを指定した場合、出力は要求した順序`[9,-3]`の2枚です。内部の0始まりのスロット番号では`[4,0]`から取り出されます。

相対座標への変換では全座標から同じ値を引くため、順序は変わりません。内部座標と出力スロットの対応は、保存latentの`h3_mfi_plan`メタデータに記録されます。

## 参照経路とノイズの設定

この節の設定は、学習と生成で対応させて使います。学習中のサンプル生成も、学習側の設定を引き継ぎます。

### 参照画像をどこに渡すか

参照画像は、Qwenが画像から特徴を取り出す経路と、DiTへ参照latentを渡す経路で使われます。`--h3_reference_route`で、どちらを使うか選択できます。

| 経路 | Qwenで参照画像を使う | DiTへ参照latentを渡す |
| --- | --- | --- |
| `dual` | はい | はい |
| `qwen_image_only` | はい | いいえ |
| `dit_latent_only` | いいえ（キャプションのみ） | はい |
| `text_only` | いいえ（キャプションのみ） | いいえ |
| `native` | `--task`に従う | `--task`に従う |

`native`以外の経路実験では、ベースモデルはRef2VA系（`--task ref2va`）を使います。経路を変える場合は、キャッシュ作成時の`--route`も合わせてください。

学習では、実際のキャッシュ内容と指定した経路の整合性を検証します。ゼロテンソルを入れて「参照なし」を模擬するわけではありません。生成では`--from_file`のプロンプトごとにも経路を指定できます。

`text_only`は参照入力なしで`--prompt`だけを指定できます。DiT参照なしの経路では、コントロール座標を相対位置の計算に使っても、その座標をDiT参照トークンとして挿入しません。

### ターゲット間でノイズを共有するか

`--h3_target_noise_coupling independent`では、ターゲットごとに独立した初期ノイズを使います。`shared`では、最初のターゲットの初期ノイズを全ターゲットへ複製します。

各ターゲット単独のノイズ分布はどちらも標準正規分布ですが、ターゲット同士のノイズの関係（共分散）が変わります。`independent`で学習したモデルは、通常、生成時も`independent`を使ってください。

## 内部仕様と再現に必要な情報

通常の利用では、まず前半の手順に従ってキャッシュ作成ツールを使ってください。この節は、キャッシュを自作する場合や、実験条件を保存・確認する場合の説明です。

### 座標と画像の扱い

インデックスは、MM-RoPEというモデル内部の位置表現に使う、符号付きの画素フレーム座標です。意味ラベルではありません。MFIは、役割の集合・数、テンソルの順序、座標の割り当てを固定しません。

各ターゲットはlatentの1スライスとして扱い、モデル出力にはターゲットに対応する部分だけを取り出します。画像へ戻すときは、VAEの時間方向にパディングを行うT=1経路で、1スライスずつ独立にデコードします。

ただし、生成中のターゲット同士はattentionで互いの情報を参照します。そのため、同じノイズを使っても、1枚ずつ別々に生成する処理とは同等ではありません。

### キャッシュを自作する場合

学習器へ渡すキャッシュには、次のデータが必要です。

- ターゲットlatent：`[B,24,N,H,W]`。`B`はバッチサイズ、`N`はターゲット数、`H,W`はlatentの空間サイズです。
- 音声データの代わりとなる、正の長さを持つ音声プレースホルダー。画像のみの学習では`audio_present=0`も必要です。
- 参照経路に応じた参照latentと、Qwenの特徴データ。

役割ごとのキャッシュを連結する場合は、各画像をT=1でエンコードし、参照latentが同一であることを確認します。そのうえで、ターゲットlatentをインデックスと同じ順序で時間方向に連結し、この作成過程も記録してください。

`qwen_image_only`と`text_only`のlatentは、DiT参照を持たないT2VAレイアウトになります。`dit_latent_only`と`text_only`のQwenキャッシュには、画像由来の特徴行を含めず、キャプションのみを保存します。

生成時も、キャプションのみの経路ではQwenへ画像参照を提示せず、DiT参照なしの経路では対応するトークン自体を省略します。既存のテキストキャッシュが選択した経路の提示内容と一致しない場合は、拒否されます。

### 条件ノイズとstrengthの計算

マスクを適用した参照latentには、学習・生成とも次の計算で条件ノイズを加えます。

```text
モデルへ渡す参照latent = c * masked_latent + (1 - c) * noise
c = h3_visual_cond_clean（既定値 0.999）
```

黒マスクの領域は`masked_latent=0`なので、既定値では`0.001 * noise`になります。`c=1`ならノイズを加えず、マスク後の値をそのまま使います。参照latentは、モデル入力時に必ず完全なクリーン状態になるわけではありません。

初期画像は、VAEの事後分布の最頻値（posterior mode）でlatentへ変換します。strengthを指定した場合は、映像と音声の両方が同じ基準sigmaから、それぞれのH3シフトを適用して開始します。strengthは基準sigmaの割合なので、シフト後の映像ノイズの線形な混合係数とは異なります。

### LoRAと一緒に保存しておくもの

LoRAメタデータには、実行全体のMFI設定と、CLIで明示したインデックスが記録されます。ただし、CLIのインデックスを省略した場合、対応する値は`default`になります。サンプルごとのキャッシュ内の座標が、そのままLoRAへ保存されるわけではありません。

LoRA単体では学習データの対応関係を復元できないため、次の情報も保存してください。

- manifest、または画像グループ・動画からの選択設定。
- キャッシュテンソルと、設定・入力ファイルの識別情報を記録した付随ファイル。
- データセット設定と、使用したモデルの識別情報。
- ターゲットの数・意味・順序・インデックス、参照経路、ノイズの共有設定、条件ノイズの設定。

キャッシュ作成ツールは入力ファイルの識別情報とモデルのフィンガープリントも記録します。これらを残すことで、後から同じ条件を確認できます。

## 互換性と制限

- MFIフラグを省略した場合、通常のH3動画、one-frame、ConvRot/NVFP4、long-durationの動作は変わりません。
- MFIは、公式の`--one_frame`モードや時間方向の伸張（temporal stretching）とは別の機能です。
- 明示的な参照座標は、Ref2VAの画像参照（最大9枚）とFL2VAの画像条件に対応します。動画から選んだフレームも、MFIには独立にエンコードした画像として渡します。
- FL2VAの学習中サンプル生成は、先頭画像のみ、末尾画像のみ、両方に対応します。入力画像ごとに1つの視覚条件インデックスが必要です。
- バッチMFI出力には音声プレースホルダーを保存しません。decode-onlyでも、古いMFIファイルに残っている音声プレースホルダーは無視します。
